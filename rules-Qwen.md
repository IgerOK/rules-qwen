# rules-Qwen.md — канон настройки Qwen Code

Единый документ переноса конфигурации агента Qwen Code на чистую машину.
Адаптация [rules-zed](https://github.com/IgerOK/rules-zed) под Qwen Code.

## §1. Глобальный QWEN.md

Создаётся в OS-зависимом пути:

- Windows: `%USERPROFILE%\.qwen\QWEN.md` (например `C:\Users\<USER>\.qwen\QWEN.md`)
- Linux: `~/.qwen/QWEN.md`
- macOS: `~/.qwen/QWEN.md`

Qwen Code также читает `AGENTS.md` в корне проекта, если он есть — дублировать
инструкции не нужно. Проектный файл — `QWEN.md` в корне репозитория (для команды)
и `.qwen/QWEN.local.md` (личное, в git не коммитить).

### Секции глобального QWEN.md

1. **Коммуникация** — лаконичные ответы на русском, без приветствий и вступлений,
   стиль «senior-разработчик». По делу, без повторов и пересказа кода из diff.
2. **Git** — перед работой проверить состояние (`git status`), коммит после каждого
   изменения. Remote и push — только по явной просьбе пользователя.
3. **Python** — проверить наличие интерпретатора, при отсутствии предложить установку.
4. **Project Bootstrapping** — в пустой папке уточнить стек у пользователя, создать
   проектный `QWEN.md`, если его нет.
5. **README** — держать `README.md` актуальным вместе с кодом.
6. **Оболочка Windows** — выбирать cmd или PowerShell там, где операция короче и
   надёжнее. Терминал Qwen Code — POSIX и искажает Windows-пути.
7. **Лимиты и экономия токенов** — см. §1.1 ниже.

### §1.1. Лимиты и экономия токенов

#### Адаптивные профили

Числовые пороги — доли от окна W. Определи W из доков модели/шлюза и зафиксируй
в проектном `QWEN.md` (строка «Окружение: W = …K, профиль: …»); если W неизвестно
или не зафиксировано — уточни у пользователя, не подставляй дефолт молча:

- **Узкое (W ≤ 128K):** чтения > 200 строк, вывод ≤ 30, handoff при 0.40·W.
- **Стандартное (129K < W ≤ 200K):** чтения > 500, вывод ≤ 50, handoff при 0.65·W.
- **Широкое (W > 200K):** чтения > 1000, вывод ≤ 100, handoff при 0.70·W.

#### Пороговые триггеры

- **0.30·W** — точечный режим: grep/структура вместо чтения файла.
- **0.55·W** — запрет на новые подзадачи; довести текущую, чекпоинт-заметку в файл.
- **0.65·W** — handoff → новый чат.

Для узкого профиля: 0.25 / 0.40 / 0.45.

#### Жёсткие лимиты

- Контекстное окно — верхняя граница, не цель. Комфортный объём: 0.75·W
  (стандарт/широкое), 0.50·W (узкое).
- Задача требует большого контекста (огромные файлы, массовые операции) —
  предупреждай до начала.
- Проверяй фактическое заполнение окна командой `/context`.

#### Точечное чтение

- Файлы > 500 строк (стандарт) / > 200 (узкое): grep/ripgrep по символу/функции,
  затем чтение диапазона (`read_file` с offset/limit).
- Не читать файл целиком, если решается фрагментом; не пересылать — только
  релевантные фрагменты.
- > 2000 строк / > 500 (узкое) — уточни: весь или фрагмент.

#### Терминал

- Вывод: `| head -50` (стандарт) / `| head -30` (узкое) / `| head -100` (широкое);
  PowerShell — `Select-Object -First N`.
- Лог > 500 строк — окном 200–500, выводы → файл-заметку.

#### Дробление длинных входов

- > 0.5·W (стандарт) / > 0.35·W (узкое) — разбей, обрабатывай последовательно.
- Промежуточные выводы → файл-заметку, не в историю чата.
- Не пересказывай обработанные части — ссылка на файл-заметку.

#### Handoff-протокол

При достижении порога handoff:

1. Запиши в `HANDOFF.md` (корень или `.notes/`): цель (1–3 строки), сделано
   (файлы/строки), текущее состояние (открытые диффы), принятые решения
   (что и почему), следующие 2–3 шага, подводные камни.
2. Новый чат: «прочитай HANDOFF.md и продолжи».
3. `HANDOFF.md` удаляй после закрытия задачи.

#### Чистый чат

- Новая крупная задача — новый чат.
- Не держи в одном чате несколько несвязанных задач.
- Изменения в `QWEN.md`/`AGENTS.md` видны в новом чате.

#### Никаких лишних MCP

- MCP — только при реальной необходимости (свежие доки, E2E, БД). Каждый сервер —
  постоянная трата токенов в каждом запросе.
- Перед подключением: покрывает ли задачу нативный инструментарий Qwen Code
  (файлы, терминал, grep, диагностика, fetch).
- Не подключать «на всякий случай».

#### Проектный QWEN.md

- Стек, версии, команды, конвенции, запретные зоны. Без секретов.
- **Записывай принятые решения и отклонённые варианты** («X сделали, Y отбросили,
  потому что Z») — экономия между сессиями.
- Не дублировать глобальные правила. Держать актуальным, как README.

## §2. Skill git-workflow

Устанавливается в `~/.agents/skills/git-workflow/SKILL.md` (см. файл
`skills/git-workflow/SKILL.md` в этом репозитории).

Проверка и настройка Git перед началом работы с кодом: установка Git (при
отсутствии), инициализация репозитория, `.gitignore`, настройки пользователя,
статус, коммит после изменений; remote и пуш — только по отдельной просьбе
пользователя.

## §3. Skill project-doctor

Устанавливается в `~/.agents/skills/project-doctor/SKILL.md` (см. файл
`skills/project-doctor/SKILL.md` в этом репозитории).

Сквозная автоматическая проверка готовности окружения проекта: целостность
зависимостей, линтеры, конфигурационные файлы, переменные окружения.

## §4. Нюансы Qwen Code

- **Skills** — подгружаются динамически, список виден в сессии. Установка —
  в `~/.agents/skills/<name>/SKILL.md`.
- **Обновления** — Qwen Code обновляется через менеджер установки; после
  обновления проверь, что skills и настройки на месте.
- **Проектный контекст** — `QWEN.md` в корне проекта (для команды) и
  `.qwen/QWEN.local.md` (личное). `AGENTS.md` тоже читается.
- **Настройки** — `~/.qwen/settings.json` (пользовательские) и
  `.qwen/settings.json` (проектные). Большинство изменений требуют перезапуска.
- **Контекстное окно** — задаётся через `contextWindowSize` в `generationConfig`
  провайдера; проверка — `/context`.
- **Режимы одобрения** — Plan / Ask Permissions / Auto-Edit / Auto / YOLO,
  переключение — Shift+Tab (или Tab на Windows).

## §5. Чек-лист настройки

1. Установить Qwen Code и Git.
2. Скачать этот проект (Download ZIP), открыть папку в Qwen Code.
3. В **новом** чате сказать: «Прочитай файл `rules-Qwen.md` и выполни инструкции
   §1–§5».
4. Проверить, что создан глобальный `~/.qwen/QWEN.md` с секциями §1.
5. Проверить, что доступны skills `git-workflow` и `project-doctor`.
6. В новом чате проверить, что правила применяются.

## Конфиденциальность

В файлах только плейсхолдеры (`<USER>`, `email@example.com` и т.п.), секретов нет.
API-ключи — только в настройках Qwen Code (`~/.qwen/settings.json`), в файлы
проекта не попадают.
