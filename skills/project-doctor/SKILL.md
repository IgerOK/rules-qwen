# 🩺 Skill: Project-Doctor Diagnostic Scenario

## Когда активировать
- При первом открытии проекта в Qwen Code Desktop.
- Если проект перестал собираться или падают тесты.

## Алгоритм выполнения:
1. **Поиск манифестов:** Просканируй корень проекта на наличие конфигурационных файлов зависимостей (`package.json`, `requirements.txt`, `pyproject.toml`, `Cargo.toml`, `go.mod`). Определи рабочий стек.
2. **Анализ зависимостей:** Проверь, развернуты ли локальные папки пакетов (`node_modules`, `.venv`, `target`). Если зависимости отсутствуют, выведи пользователю список необходимых команд для установки, но **не запускай их автоматически** без одобрения.
3. **Проверка переменных окружения:** Проверь наличие файлов `.env` или `.env.example`. Убедись, что проект укомплектован именами переменных. *Внимание: Никогда не выводи значения секретных ключей в тело чата.*
4. **Проверка линтеров:** Найди файлы конфигурации качества кода (`.eslintrc`, `ruff.toml`, `.prettierrc`). Проверь работоспособность линтера через тестовый запуск в терминале (например, `npm run lint -- --dry-run`).
5. **Итоговый отчет:** Сформируй краткий структурированный Markdown-отчет для разработчика:
   - ✅ Что настроено правильно.
   - ❌ Что сломано или отсутствует.
   - 🛠️ Конкретные консольные команды для быстрого исправления ситуации.
